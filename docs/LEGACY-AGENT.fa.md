# پل ایران — CF Reverse v0.2.0

این بسته نسخهٔ آزمایشی اجرایی برای هدف شماست: کاربران به سنایی روی ایران متصل می‌شوند؛ Worker اتصال WSS را به ایران آغاز می‌کند؛ Agent درخواست‌های SOCKS محلی را از همان کانال به Worker می‌فرستد؛ Worker اتصال TCP مقصد را باز می‌کند. هیچ VPS خارجی، ProxyIP عمومی یا relay شخص ثالث در کد قرار داده نشده است.

**وضعیت:** ۱۸ تست محلی موفق و بسته‌بندی Wrangler موفق؛ روی حساب واقعی Cloudflare و VPS ایران آزمایش نشده. اجرای `wrangler dev` در محیط ساخت با خطای `uv_interface_addresses` متوقف شد. این بسته آمادهٔ آزمایش محدود است، نه سرویس تجاری تأییدشده.

## مسئولیت اجزا

| جزء | مسئولیت |
|---|---|
| سنایی / Xray ایران | کاربران، UUID، انقضا، سهمیه و حسابداری |
| Agent روی همان سرور ایران | SOCKS5 محلی و پذیرش کانال‌هایی که Worker آغاز کرده |
| Worker + Durable Objects | اتصال به ایران، خروج TCP، داشبورد فارسی، بازیابی کانال |
| داشبورد Worker | وضعیت کانال‌ها و شروع/توقف؛ مدیریت کاربران همچنان در سنایی است |

## محدودیت‌های تعیین‌کننده

- فقط TCP با مقصد IPv4 یا نام دامنه؛ پورت‌های پیش‌فرض ۸۰ و ۴۴۳. UDP، QUIC و IPv6 این نسخه پشتیبانی نمی‌شوند.
- Cloudflare اتصال خام TCP به IPهای خودش و شبکه‌های خصوصی را محدود می‌کند. بنابراین همهٔ سایت‌ها با این معماری باز نمی‌شوند. افزودن ProxyIP خارجی وابستگی به زیرساخت خارجی را بازمی‌گرداند و در این نسخه انجام نشده است.
- خروجی ثابت یا کشور خروجی تضمین نمی‌شود. قطع مسیر بین‌الملل را با تغییر جهت آغاز اتصال نمی‌توان به‌صورت تضمینی حل کرد.
- کانال خروجی DO قابلیت hibernation ندارد؛ مدت فعالیت، پیام‌ها و سهمیهٔ حساب می‌توانند هزینه داشته باشند. «بدون VPS خارجی» به معنی «رایگان و نامحدود» نیست.
- پیش‌فرض یک کانال با چهار TCP هم‌زمان است. CHANNELS بین ۱ تا ۸ در هر دو سمت باید یکسان باشد؛ سقف کل ۳۲ اتصال، نه ۳۲ کاربر. یک مرورگر چندین اتصال می‌سازد. سقف چهار، انتخاب محافظه‌کارانهٔ این پیاده‌سازی است، نه ادعای سقف ثابت پلتفرم.
- هر جریان پنجرهٔ ۱۲۸ کیبی‌بایتی و قطعهٔ حداکثر ۱۶ کیبی‌بایتی دارد. توقف مصرف‌کننده باعث کنترل جریان می‌شود. تأخیر شبکه سرعت را محدود می‌کند.
- اتصال TCP قطع‌شده ادامه داده نمی‌شود؛ پس از بازیابی کانال فقط اتصال‌های جدید برقرار می‌شوند. جریان بی‌فعالیت پس از پنج دقیقه بسته می‌شود.
- آمار داشبورد تشخیصی است و با بازسازی DO صفر می‌شود. مرجع حجم کاربران سنایی است.

## ۱. آماده‌سازی ایران

Node.js نسخهٔ ۲۲ یا بالاتر و یک دامنهٔ عمومی با TLS معتبر لازم است. Agent در هر دو پورت فقط روی 127.0.0.1 گوش می‌دهد. سنایی باید در همان namespace شبکه باشد؛ اگر Docker با شبکهٔ جدا دارید، این تنظیم localhost بدون تغییر معماری کار نمی‌کند.

پوشهٔ پروژه را در `/opt/cf-reverse` قرار دهید و داخل آن اجرا کنید:

```bash
npm ci --omit=dev --ignore-scripts
openssl rand -hex 32
```

خروجی openssl را به‌عنوان TUNNEL_TOKEN در فایل `/etc/cf-reverse.env` قرار دهید؛ قالب در `deploy/agent.env.example` است. نمونهٔ داخل قالب رمز واقعی نیست. فایل را با مجوز ۶۰۰ نگه دارید.

```bash
sudo useradd --system --home /nonexistent --shell /usr/sbin/nologin cf-reverse
sudo chmod 600 /etc/cf-reverse.env
sudo cp deploy/cf-reverse.service /etc/systemd/system/cf-reverse.service
sudo systemctl daemon-reload
sudo systemctl enable --now cf-reverse
curl http://127.0.0.1:8765/health
```

اگر کاربر سیستم قبلاً وجود دارد دستور useradd را تکرار نکنید. مسیر Node در service باید با `command -v node` سازگار باشد؛ نصب Node زیر پوشهٔ root با این سرویس مناسب نیست. پوشهٔ پروژه باید برای کاربر سرویس خواندنی باشد.

دامنهٔ ایران را DNS-only به سرور اشاره دهید و مسیر `/reverse` را با TLS معتبر به `127.0.0.1:8765` متصل کنید. نمونهٔ Caddy در deploy است. پورت‌های 8765 و 10808 را عمومی نکنید. نمونهٔ Caddy را با کانفیگ موجود ادغام کنید؛ اگر Xray پورت 443 را گرفته است، از listener/پورت آزاد مانند 8443 با TLS معتبر یا reverse proxy موجود استفاده کنید و همان پورت را در IRAN_RELAY_URL بنویسید. گرفتن گواهی نیازمند دسترسی مناسب challenge است. کانفیگ فعال سنایی را بازنویسی نکنید.

## ۲. نصب Worker از ویندوز یا لینوکس

روی رایانهٔ دارای Node، در ریشهٔ پروژه:

```bash
npm ci --ignore-scripts
npx wrangler login
```

در `worker/wrangler.toml` آدرس IRAN_RELAY_URL را به `https://YOUR-IRAN-DOMAIN/reverse` تغییر دهید. CHANNELS ابتدا ۱ بماند.

```bash
npx wrangler secret put TUNNEL_TOKEN --config worker/wrangler.toml
npx wrangler secret put ADMIN_TOKEN --config worker/wrangler.toml
npm run worker:deploy
```

TUNNEL_TOKEN باید همان رمز ایران باشد. ADMIN_TOKEN یک رمز تصادفی مستقل حداقل ۳۲ کاراکتری باشد. این دو توکن را داخل سورس یا پیام عمومی قرار ندهید.

آدرس Worker را باز کنید، با ADMIN_TOKEN وارد شوید و کانال را فعال کنید. کانال‌ها در نصب تازه خاموش‌اند. Alarm تقریباً هر ۲۰ ثانیه و Cron هر دقیقه بازیابی را پیگیری می‌کنند؛ تضمین زمان بازیابی نیست. توقف در ذخیره‌سازی ماندگار می‌ماند. نام Worker این نسخه با نمونهٔ قبلی فرق دارد؛ پیش از فعال‌سازی نسخهٔ جدید، کانال قدیمی را متوقف کنید. پروتکل نسخه‌های ۰.۱ و ۰.۲ سازگار نیست.

## ۳. اتصال سنایی

ابتدا از تنظیمات Xray نسخهٔ پشتیبان بگیرید. برای یک inbound آزمایشی، برچسب واقعی آن را به این فرمان بدهید:

```bash
node scripts/xray-config.mjs inbound-443
```

خروجی فقط قطعات تنظیمات است، نه کانفیگ کامل. دو outbound را اضافه کنید و قوانین تولیدشده را، با همین ترتیب، پیش از قوانین عمومیِ منطبق بر inbound آزمایشی قرار دهید. تنظیم API و سایر inboundها را حفظ کنید. قانون UDP مسدود است تا به خروجی مستقیم سقوط نکند. برای DNS کلاینت از DoH مبتنی بر TCP قابل‌دسترسی استفاده کنید؛ این برنامه سرور DNS نیست. `domainStrategy: AsIs` از resolve اجباری همهٔ نام‌های مقصد در ایران جلوگیری می‌کند. geodata موردنیاز قانون `geoip:private` باید در Xray موجود باشد.

## ۴. پذیرش روی شبکهٔ واقعی

۱. `/health` ایران و داشبورد باید یک کانال متصل نشان دهند.
۲. روی ایران یک مقصد HTTPS تحت کنترل خودتان که پشت Cloudflare نیست را آزمایش کنید:

```bash
curl --fail --max-time 30 --socks5-hostname 127.0.0.1:10808 https://YOUR-TEST-HOST/
```

۳. فایل معلوم را دانلود و SHA-256 آن را مقایسه کنید؛ سپس یک کاربر واقعیِ inbound آزمایشی را متصل کنید.
۴. افزایش حجم، انقضا و قطع دسترسی کاربر در سنایی را بررسی کنید. این قسمت در محیط ساخت با خود Xray اجرا نشده است.
۵. قطع Agent، اتصال مجدد، محدودیت چهار جریان، یک مقصد مسدودشده و DNS را جداگانه آزمایش کنید.
۶. هزینه و CPU/Memory را در داشبورد Cloudflare پایش کنید. تا عبور از این مراحل مسیر قبلی را حذف نکنید.

بازگشت: قوانین و outboundهای آزمایشی را حذف و کانفیگ قبلی Xray را بازگردانید؛ همهٔ کانال‌ها را در داشبورد متوقف کنید و سپس سرویس Agent را خاموش کنید.

```bash
npm ci --ignore-scripts
npm test
npm run worker:check
```
