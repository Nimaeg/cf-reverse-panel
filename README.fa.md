# پنل ریورس ایران — نسخهٔ ۰.۳

پنل فارسی تحت وب با دو فیلد **کانفیگ VLESS سرور ایران** و **Reverse Tag** و دکمهٔ **ذخیره و اتصال به ایران**. Worker مستقیماً با پروتکل VLESS Reverse به Xray ایران متصل می‌شود. در این حالت نیازی به Agent جداگانه نیست.

**آزمایش‌شده:** اتصال واقعی به Xray 26.10.21 روی loopback، در دو حالت TCP+TLS و WebSocket+TLS؛ انتقال رفت‌وبرگشتی ۸ مگابایت با SHA-256 یکسان؛ قطع و اتصال مجدد؛ رد UUID فاقد مجوز ریورس؛ چهار جریان هم‌زمان؛ بازیابی تنظیمات رمزگذاری‌شده. فقط API سوکت Cloudflare و ذخیره‌سازی DO در این تست‌ها با معادل Node جایگزین شده‌اند. این بسته هنوز روی حساب واقعی Cloudflare و سرور ایران شما اجرا نشده است.

## استفادهٔ روزمره

پس از نصب اولیهٔ Worker و آماده‌کردن Xray ایران:

1. آدرس Worker را باز کن و با کلید مدیریت وارد شو.
2. لینک `vless://…` یا JSON خروجی VLESS سرور ایران را در فیلد کانفیگ پیست کن.
3. نام تگ ریورس را در فیلد دوم بنویس و «ذخیره و اتصال به ایران» را بزن.
4. پنل پس از تأیید کانال توسط Xray، «متصل» نشان می‌دهد. خطا، حجم ترافیک، اتصال‌های فعال، قطع اتصال و اتصال مجدد هم در همان صفحه هستند.

**پیش‌نیاز مهم:** UUID واردشده باید در Xray ایران مجوز `reverse` داشته باشد. لینک معمولی کاربران چنین مجوزی ندارد. پنل تگ و Routing را روی سرور نمی‌سازد؛ Reverse Tag نام محلی اتصال است و در پیام VLESS فرستاده نمی‌شود. سرور با UUID، حساب ریورس و تگ خروجی خودش را انتخاب می‌کند. بهتر است در پنل همان نام تگ سمت ایران را بنویسی؛ برابری این نام قابل تأیید خودکار نیست.

## ۱. نصب Worker

روی رایانه‌ای با Node.js نسخهٔ ۲۲ یا بالاتر، در پوشهٔ پروژه اجرا کن:

```bash
npm ci --ignore-scripts
npx wrangler login
```

یک ADMIN_TOKEN تصادفی مستقل با حداقل ۳۲ کاراکتر بساز؛ مثلاً خروجی `openssl rand -hex 32`. آن را در فرمان بعد وارد کن:

```bash
npx wrangler secret put ADMIN_TOKEN --config worker/wrangler.toml
npm run worker:deploy
```

آدرس نمایش‌داده‌شده توسط Wrangler، آدرس پنل است. همین دو دستور برای تنظیم رمز و استقرار پنل جدید کافی‌اند؛ `TUNNEL_TOKEN` و `IRAN_RELAY_URL` فقط به حالت Agent قدیمی مربوط‌اند. اتصال تازه تا زمان ثبت کانفیگ خاموش است. در `worker/wrangler.toml` فهرست `ALLOWED_PORTS` به‌صورت پیش‌فرض `80,443` است؛ در صورت نیاز پورت‌های مشخص دیگری را اضافه و دوباره deploy کن.

نام Worker همان `cf-reverse-iran-v2` نگه داشته شده تا نسخهٔ ۰.۲ قابل ارتقا باشد. مهاجرت `v2-native-reverse` یک Durable Object جدا برای حالت جدید اضافه می‌کند. هنگام انتقال از Agent به حالت بومی، کانال‌های قدیمی را در `/legacy` خاموش کن و Routing آزمایشی را مطابق بخش بعد تغییر بده. کد و راهنمای Agent قبلی در `docs/LEGACY-AGENT.fa.md` باقی مانده است.

## ۲. آماده‌سازی Xray ایران

دامنهٔ DNS-only که مستقیم به سرور ایران اشاره کند، پورت قابل‌دسترسی و گواهی TLS معتبر لازم است. آدرس سرور و SNI باید یکسان باشند. TLS با گواهی نامعتبر یا self-signed در Worker پذیرفته نمی‌شود. گواهی محلی تست فقط در adapter آزمون به‌عنوان CA مورد اعتماد اضافه شده است.

از Xray پشتیبان VLESS Reverse استفاده کن؛ نسخهٔ مرجع آزمون این بسته **26.10.21** است. در inbound مخصوص اتصال Worker، کاربر جداگانه‌ای با چنین تنظیمی لازم است:

```json
{
  "id": "UUID-مخصوص-Worker",
  "email": "worker-reverse",
  "reverse": { "tag": "iran-reverse" }
}
```

این قطعه JSON قابل اجرا نیست تا UUID واقعی جایگزین شود. `decryption` ورودی و `encryption` لینک باید `none` باشند، Flow خالی باشد، و انتقال TCP/RAW یا WS با TLS تنظیم شود. UUID ریورس را در اختیار کاربران عادی قرار نده.

در Routing ایران، **ورودی کاربران** را به خروجی `iran-reverse` هدایت کن. این خروجی توسط Xray از حساب reverse ساخته می‌شود؛ یک outbound عادی با همین نام نساز. UDP کاربران را به یک outbound از نوع blackhole بفرست تا به مسیر مستقیم سقوط نکند. پنل سنایی باید این تنظیمات را در خروجی واقعی Xray حفظ کند؛ اگر نسخهٔ پنل تو فیلد reverse را نمی‌شناسد، وارد کردن لینک در این پنل به‌تنهایی مشکل را حل نمی‌کند. تنظیمات فعال سنایی را با فایل نمونه جایگزین نکن.

### ساخت نمونهٔ مستقل برای آزمایش

این ابزار یک پوشهٔ جدید شامل کانفیگ کامل Xray، لینک مخصوص Worker، تگ، و لینک کاربر آزمایشی می‌سازد. UUIDها هر بار تصادفی و مجزا هستند. فایل موجود را بازنویسی نمی‌کند و هیچ سرویسی را تغییر نمی‌دهد:

```bash
node scripts/native-server-config.mjs --server iran.example.com --tag iran-reverse --transport ws --port 443 --users-port 8443 --cert /etc/letsencrypt/live/iran.example.com/fullchain.pem --key /etc/letsencrypt/live/iran.example.com/privkey.pem --out generated-native
```

دامنه، مسیر گواهی و دو پورت آزاد را با مقادیر خودت جایگزین کن؛ برای TCP از `--transport tcp` استفاده کن. فایل `generated-native/xray-server.json` برای Xray مستقل است. ابتدا اعتبارسنجی کن:

```bash
xray run -test -c generated-native/xray-server.json
```

سپس آن را در یک سرویس آزمایشی با دسترسی خواندن گواهی‌ها اجرا کن. `reverse-link.txt` و `reverse-tag.txt` را در پنل Worker وارد کن. `test-user-link.txt` مخصوص کلاینت کاربر است. این فایل‌ها حاوی اعتبارنامه‌اند؛ آن‌ها را عمومی نکن. در سنایی، کاربر، سهمیه، انقضا و Routing را در خود پنل مدیریت کن؛ نمونهٔ مستقل جایگزین حسابداری سنایی نیست.

## ۳. پذیرش روی سرور خودت

پس از مشاهدهٔ «متصل»، کلاینت VLESS را با لینک کاربر به ورودی کاربران ایران وصل کن. ابتدا یک مقصد HTTPS تحت کنترل خودت که پشت Cloudflare نیست را باز کن و یک فایل با هش معلوم را دریافت کن. افزایش شمارنده‌ها را در داشبورد ببین؛ سپس قطع و اتصال مجدد را امتحان کن. صحت سهمیه و انقضای کاربران را در سنایی جداگانه بررسی کن. «متصل» به معنی تأیید کانال ریورس است؛ مسیر کاربران، DNS و دسترسی همهٔ مقصدها را تضمین نمی‌کند.

## محدودیت‌های این نسخه

- فقط VLESS روی **TCP/RAW+TLS** یا **WebSocket+TLS**، با `encryption=none` و Flow خالی.
- REALITY، Vision، VLESS Encryption، XHTTP، gRPC، early data، IPv6 و UDP پشتیبانی نمی‌شوند. DNS کلاینت باید از روشی مبتنی بر TCP مثل DoH قابل‌دسترسی استفاده کند.
- TLS استاندارد Worker استفاده می‌شود. اثر انگشت Chrome/Firefox واردشده اعمال نمی‌شود و پنل این موضوع را اعلام می‌کند. SNI جدا از آدرس سرور پشتیبانی نمی‌شود.
- یک کانال بومی و چهار اتصال TCP هم‌زمان؛ این عدد تعداد کاربر نیست. `CHANNELS` فقط حالت Agent قدیمی را کنترل می‌کند. این نسخه برای آزمایش محدود است.
- اتصال خام TCP Worker به IPهای Cloudflare و شبکه‌های خصوصی محدود است؛ در نتیجه همهٔ سایت‌ها با این معماری باز نمی‌شوند. هیچ ProxyIP یا سرور واسط خارجی در برنامه قرار داده نشده است.
- جهت آغاز اتصال، مصونیت در برابر قطع اینترنت یا فیلترینگ را تضمین نمی‌کند. کشور و IP خروجی ثابت تضمین نمی‌شوند. مصرف Worker و Durable Objects ممکن است هزینه داشته باشد.
- قطع کانال، جریان‌های TCP موجود را قطع می‌کند؛ پس از بازیابی، اتصال‌های جدید کار می‌کنند. جریان بی‌فعالیت حدود دو دقیقه بعد بسته می‌شود. Native mux تضمین half-close ندارد.
- تلاش مجدد با Alarm و Cron انجام می‌شود؛ زمان دقیق بازیابی تضمین‌شده نیست. ریورس در حال فعالیت hibernation ندارد.
- کلید مدیریت در حافظهٔ صفحه نگه داشته می‌شود. کانفیگ ذخیره‌شده با AES-GCM و کلیدی مشتق از ADMIN_TOKEN رمزگذاری می‌شود. تغییر ADMIN_TOKEN نیازمند واردکردن دوبارهٔ کانفیگ است. خروج از پنل کانال را قطع نمی‌کند؛ برای آن از «قطع اتصال» استفاده کن.

## بررسی توسعه

```bash
npm test
npm run worker:check
```

تست‌های Xray بدون مسیر باینری به‌صراحت skip می‌شوند. برای اجرای آن‌ها، باینری رسمی Linux نسخهٔ مرجع را پس از بررسی digest دریافت کن و اجرا کن:

```bash
XRAY_BIN=/absolute/path/to/xray npm test
```

OpenSSL هم برای ساخت گواهی موقت تست لازم است. بسته‌بندی Wrangler در محیط ساخت موفق بود؛ اجرای خود `wrangler dev` در این محیط با خطای `uv_interface_addresses` متوقف شده بود. تست Node با Xray واقعی جای تأیید اجرای دیتاسنتر Cloudflare را نمی‌گیرد.
